채점 항목 

1-1 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 “10.101.0.0/16"이 출력되는지 확인합니다. 

$ aws ec2 describe-vpcs --filter Name=tag:Name,Values=ws-vpc --query "Vpcs[].CidrBlock" 

1-2 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 "nat-" 로 시작하는 문구가 출력되는지 확인합니다. 

$ aws ec2 describe-route-tables --filter Name=tag:Name,Values=ws-priv-rt-a \ 

--query "RouteTables[].Routes[].NatGatewayId" 

1-3 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 "nat-" 로 시작하는 문구가 출력되는지 확인합니다. 

$ aws ec2 describe-route-tables --filter Name=tag:Name,Values=ws-priv-rt-c \ 

--query "RouteTables[].Routes[].NatGatewayId" 

1-4 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 "igw-" 로 시작하는 문구가 출력되는지 확인합니다. 

$ aws ec2 describe-route-tables --filter Name=tag:Name,Values=ws-pub-rt \ 

--query "RouteTables[].Routes[].GatewayId" 

1-5 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 “ap-northeast-2a“가 출력되는지 확인합니다. 

$ aws ec2 describe-subnets --filter Name=tag:Name,Values=ws-priv-a --query \ 

"Subnets[].AvailabilityZone" 

1-6 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 “ap-northeast-2c“가 출력되는지 확인합니다. 

$ aws ec2 describe-subnets --filter Name=tag:Name,Values=ws-pub-c --query \ 

"Subnets[].AvailabilityZone" 

1-7 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 “ap-northeast-2a", “ap-northeast-2c"가 출력되는지 확인합니다. 

$ aws elbv2 describe-load-balancers \
--query LoadBalancers[?LoadBalancerName==gateway-alb-pub'].AvailabilityZones[].ZoneName" 

2-1 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 “wsi-cluster“가 출력되는지 확인합니다. 

$ aws ecs describe-clusters --cluster ws-cluster --query "clusters[].clusterName" 

2-2 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 “gateway-td“가 출력되는지 확인합니다. 

$ aws ecs describe-task-definition --task-definition gateway-td \ 

--query "taskDefinition.containerDefinitions[].name" 

2-3 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 “product-td“가 출력되는지 확인합니다. 

$ aws ecs describe-task-definition --task-definition product-td \ 

--query "taskDefinition.containerDefinitions[].name" 

2-4 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 ACTIVE가 출력되는지 확인합니다. 

$ aws ecs describe-services --cluster ws-cluster --services gateway-svc \ 

--query "services[].status" 

2-5 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 ACTIVE가 출력되는지 확인합니다. 

$ aws ecs describe-services --cluster ws-cluster --services product-svc \ 

--query "services[].status" 

2-6 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 이미지 마지막이 latest 가 아닌지 확인합니다.
(latest가 포함되면 감점) 

$ aws ecs describe-task-definition --task-definition gateway-td \ 

--query "taskDefinition.containerDefinitions[].image" 

2-7 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 이미지 마지막이 latest 가 아닌지 확인합니다.
(latest가 포함되면 감점) 

$ aws ecs describe-task-definition --task-definition product-td \ 

--query "taskDefinition.containerDefinitions[].image" 

2-8 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 "CRITICAL“, "HIGH“, "MEDIUM“, "LOW“ 중 어떤 것도 출력되지 않는지 확인 합니다.(출력 되면 감점) 

$ aws ecr describe-image-scan-findings --repository-name gateway \ 

--image-id imageTag=v1.0.0 --query "imageScanFindings.findingSeverityCounts"  

2-9 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 "CRITICAL“, "HIGH“, "MEDIUM“, "LOW“ 중 어떤 것도 출력되지 않는지 확인 합니다.(출력 되면 감점)
 

$ aws ecr describe-image-scan-findings --repository-name product \ 

--image-id imageTag=v1.0.0 --query "imageScanFindings.findingSeverityCounts" 

2-10 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 4 이상의 숫자가 출력되는지 확인합니다. 

$ aws ecs describe-clusters --cluster wsi-ecs --query "clusters[].runningTasksCount" 

2-11 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 "subnet-“로 시작하는 문자열이 2개 이상 출력되는지 확인합니다. 

$ aws ecs describe-services --cluster ws-cluster --services gateway-svc \ 

--query "services[].networkConfiguration.awsvpcConfiguration[].subnets[]" 

2-12 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 "subnet-“로 시작하는 문자열이 2개 이상 출력되는지 확인합니다. 

$ aws ecs describe-services --cluster ws-cluster --services product-svc \ 

--query "services[].networkConfiguration.awsvpcConfiguration[].subnets[]" 

2-13 

1) Gateway 컨테이너에 SHELL로 접근합니다. 

2) 아래 명령어 입력 후 CONN_PRODUCT에 매핑된 아이피가 존재 하는지 확인합니다. 

$ export | grep -i CONN_PRODUCT 

   (편법으로 풀었다고 판단될 시 ECS namespace와 ecs-service-connect에 해당하는 proxy-container가 추가 되었는지 확인) 

2-14 

1) Gateway 컨테이너에 SHELL로 접근합니다. 

2) 아래 명령어 입력 후 {"status": "OK", "app": "product"}가 출력 되는지 확인합니다. 

$ curl http://product/health 

   (편법으로 풀었다고 판단될 시 ECS namespace와 ecs-service-connect에 해당하는 proxy-container가 추가 되었는지 확인) 

3-1 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 ACTIVE 라고 출력 되는지 확인합니다. 

$ aws dynamodb describe-table --table-name "product" --query "Table.TableStatus" 

3-2 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 PAY_PER_REQUEST 라고 출력 되는지 확인합니다. 

$ aws dynamodb describe-table --table-name "product" \ 

 --query "Table.BillingModeSummary.BillingMode" 

3-3 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력 후 true 라고 출력 되는지 확인합니다. 

$ aws dynamodb describe-table --table-name "product" \ 

 --query "Table.DeletionProtectionEnabled" 

3-4 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력하여 하나 이상의 Backup이 존재 하는지 확인합니다.
("BackupSummaries": [] 만 나오면 틀린것으로 간주) 

$ aws dynamodb list-backups --table-name product 

3-5 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어 입력하여 SSE에 사용한 KMS Arn이 출력 되며, 해당 KMS가 선수의 계정에 있는것인지 확인 합니다. 

$ aws dynamodb describe-table --table-name product \ 

 --query "Table.SSEDescription.KMSMasterKeyArn" 

3-6 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 아래 명령어를 입력해 데이터 삽입을 위한 요청이 성공하여 result가 added인지 확인합니다.
3-7 채점을 위하여 결과값으로 출력된 uuid를 기록 합니다. 

$ curl --silent -X POST -H "Content-Type: application/json" \ 

-d '{"name": "mug", "owner": "jenkins_choi"}' http://${ALB}/v1/item 

3-7 

1) SSH를 통해 Bastion 서버에 접근합니다. 

2) 3-6에서 출력된 uuid를 활용해 아래 명령어를 입력하여 mug가 출력 되는지 확인합니다. 

$ curl --silent -X GET http://${ALB}/v1/item?uuid=<<3-6 출력 ID>> 

4-1 

1) 웹 브라우저를 사용해 AWS 콘솔에 접속합니다. 

2) CloudWatch 페이지로 이동하여 왼쪽 탭에서 대시보드(Dashboard)를 클릭합니다. 

3) ProductService 이름의 대시보드가 생성되어 있는지 확인합니다. 

 

4-2 

1) 웹 브라우저를 사용해 AWS 콘솔에 접속합니다. 

2) CloudWatch에서 선수가 구성한 "ProductService" 대시보드에 접근합니다. 

3) EC2의 CPU, Network를 확인 할 수 있는 그래프가 있는지 확인합니다. 

4) ALB의 4xx, 5xx 에러를 확인 할 수 있는 그래프가 있는지 확인합니다. 

4-3 

1) 웹 브라우저를 사용해 AWS 콘솔에 접속합니다. 

2) CloudWatch 페이지로 이동하여 왼쪽 탭에서 모든 경보(All alrams)를 클릭합니다. 

3) ALB 4xx에 대한 alram이 생성 되어 있고, 현재 정상(OK) 상태인지 확인합니다. 

4) Bastion에 SSH로 접근하여 아래 명령어를 빠른 속도로 20회 이상 입력 합니다. (1분 내에) 

$ curl -X GET http://<ALB>/v1/errors4xx 

5) AWS 콘솔에서 경보를 확인해 4xx 상태가 "정상(OK)"에서 다른것으로 변경 됐는지 확인합니다.(curl 명령어 입력 후 최대 5분 대기 가능) 

4-4 

1) 웹 브라우저를 통해 AWS 콘솔에서 ProductService 대시보드에 접근합니다. 

2) 그래프에서 ALB의 4xx 가 위 명령어를 입력한 시점에 높아 졌는지 확인합니다. 

4-5 

1) 웹 브라우저를 사용해 AWS 콘솔에 접속합니다. 

2) CloudWatch 페이지로 이동하여 왼쪽 탭에서 Container Insights를 클릭합니다. 

 

3) Gateway와 Product task 들에 대해 CPU Utilization, Memory Utilization을 확인합니다. 

4-6 

1) 웹 브라우저를 사용해 AWS 콘솔에 접속합니다. 

2) CloudWatch 페이지로 이동하여 왼쪽 탭에서 로그 그룹을 클릭합니다. 

3) /ws/ecs/product, /ws/ecs/gateway 두개의 로그그룹이 존재 하는지 확인합니다. 

 

4-7 

1) 웹 브라우저를 사용해 AWS 콘솔에 접속합니다. 

2) CloudWatch 로그 그룹에서 /ws/ecs/product를 클릭합니다. 

3) mug 를 검색하여 나오는 로그가 있는지 확인 합니다.
