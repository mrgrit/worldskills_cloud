  1. 문제에 제시된 괄호 <>는 변수를 뜻함으로 선수가 적절히 변경하여 사용해야 합니다.
  2. Security Group의 80/443 outbound는 anyopen하여 사용할 수 있도록 합니다.
  3. 과제 종료 전 실행 중인 테스트 및 부하를 중지하여 서버에 문제가 없도록 해야 합니다.
  4. Tag 정보가 맞지 않거나 권한 문제가 생겨 채점이 불가하지 않도록 주의합니다.
  5. 각 문제에서 요구하는 AWS region에 리소스를 생성하도록 합니다.
  6. 채점시 cloud shell을 이용해 진행합니다. 브라우저를 통해 접근하며 권한 및 접속 문제가 없도록 주의합니다.

3. Shared network storage

해당 문제는 ap-northeast-1(도쿄) 리전을 사용합니다. EFS를 사용하여 Auto scaling group의 인스턴스 간에 파일 데이터를 공유하고자 합니다. ASG가 scale out되어 새로운 인스턴스가 생성될 경우 자동으로 EFS에 접근 가능하도록 구성하세요.

VPC 구성

  • Auto scaling group과 EFS를 배포할 VPC를 구성합니다.
항목 값
VPC name tag sharing-vpc
Subnet name tag sharing-subnet-a, sharing-subnet-b
Subnet CIDR 10.100.0.0/24, 10.100.1.0/24
Subnet availability zone ap-northeast-1a, ap-northeast-1b

Auto scaling group 구성

  • EC2 auto scaling group을 생성합니다.
  • 만약 새로운 인스턴스가 생성될 경우 자동으로 EFS mount를 수행해야 하며, /mnt/efs 경로에 마운트 되어야 합니다.
  • 인스턴스에 접속하기 위해 SSM을 사용할 수 있도록 설정합니다.
주의

만약 SSM 접근이 불가능 할 경우 채점에 불이익이 있을 수 있습니다.

항목 값
Auto scaling group name sharing-asg
AMI Amazon Linux 2023
Instance size t3.micro
Minimum size 2

EFS 구성

  • 네트워크 파일 시스템을 구축하기 위해 EFS를 생성합니다.
  • EFS는 sharing-vpc에 생성하도록 합니다.
  • 자주 사용하지 않는 데이터로 인한 비용을 줄이기 위해 또한 30일이 지나면 IA storage class를 사용하도록 설정합니다.
  • 또한 EFS의 storage는 KMS로 암호화 되어야 합니다.
  • EFS name: sharing-efs
  • Subnet: sharing-subnet-a, sharing-subnet-b

4. Query from S3

해당 문제는 ap-northeast-2(서울) 리전을 사용합니다. 직원들의 연봉과 직장 생활 만족도에 대한 상관관계를 연구하기 위해 설문조사를 진행하였습니다. 설문 조사의 결과는 csv파일로 제공되며, S3에 업로드 한 뒤 Athena를 사용하여 연구에 필요한 쿼리를 수행해야 합니다. 주어진 csv파일은 수정하지 않도록 합니다.

S3 구성

  • 연구에 사용할 데이터를 업로드 하기 위해 S3 버킷을 생성합니다.
항목 값
Bucket name korea-skills-research-data-<선수 비번호>
employee.csv 업로드 위치 s3://korea-skills-research-data-<선수 비번호>/employee/
survey.csv 업로드 위치 s3://korea-skills-research-data-<선수 비번호>/survey/

Athena 구성

  • 연구원들이 Athena를 사용하여 연구를 수행할 수 있도록 구성합니다.
  • 과도한 사용으로 인해 비용을 과다 사용하는 것을 막기 위해 쿼리당 1GB의 데이터만 스캔할 수 있도록 설정합니다.
  • 쿼리의 결과는 S3 버킷으로 업로드 하도록 합니다.
항목 값
Athena work group research
Query result bucket korea-skills-research-result-<선수 비번호>
Glue database name research
Glue table names employee, survey
employee table columns emp_id, name, salary
survey table columns emp_id, response
참고

배포된 employee.csv, survey.csv는 첫 줄이 헤더(emp_id,name,salary / emp_id,response)입니다. 문제지에는 언급이 없으나, 채점기준 2-7(불필요한 데이터 제거)은 employee 테이블에서 헤더 행이 데이터로 조회되지 않는지 확인합니다.

또한 다음과 같은 saved query를 생성하도록 합니다.

  • research-query1
    • 모든 직원의 response 평균
    • 쿼리 결과는 result라는 column 하나만 존재해야 합니다.
  • research-query2
    • salary >= 70000인 직원들의 response 평균
    • 쿼리 결과는 result라는 column 하나만 존재해야 합니다.

5. Fine-grained IAM policy

해당 문제는 ap-northeast-2(서울) 리전을 사용합니다. 직원이 DynamoDB 테이블을 조작할 때 실수를 방지하고자 합니다. IAM policy를 작성하여 정해진 리소스와 방법으로만 DynamoDB에 접근할 수 있도록 해야 합니다.

DynamoDB 구성

  • DynamoDB 테이블을 생성합니다.
  • 테이블이 실수로 삭제하는 것을 방지하고, KMS로 암호화해야 합니다.
  • Table name: catalog, secret
  • Partition key: name (S)

IAM 구성

  • 직원이 사용할 IAM role과 policy를 생성합니다.
  • 채점 전 employee-role에 employee-policy 하나만 정책이 적용되어 있어야 합니다.
  • employee-role은 root를 포함하여 선수의 계정에 존재하는 모든 user와 role이 assume 할 수 있도록 구성합니다.
  • IAM role name: employee-role
  • IAM policy name: employee-policy
주의

만약 role assume이 불가능 할 경우 채점에 불이익이 있을 수 있습니다.

employee-policy는 다음과 같은 정책을 가져야 합니다.

  • catalog 테이블만 접근 가능
  • key의 이름이 name과 type인 요청만 허용
    • ex) 성공 - PutItem '{"name": {"S": "beef"}, "type": {"S": "food"}}'
    • ex) 성공 - GetItem '{"name": {"S": "beef"}}'
    • ex) 실패 - PutItem '{"name": {"S": "ball"}, "size": {"S": "big"}}'

6. MySQL with Lambda

해당 문제는 ap-northeast-2(서울) 리전을 사용합니다. Lambda를 사용하여 RDS에 있는 테이블을 조작하고자 합니다. 단, VPC 내부에 Lambda와 RDS를 구성하여 RDS가 인터넷에 노출되지 않도록 합니다. VPC와 서브넷은 자유롭게 구성합니다.

Lambda 구성

  • Lambda 함수를 생성합니다.
  • Lambda의 코드는 Python으로 작성해야 하며, 코드는 KMS로 암호화 되어야 합니다.
  • MySQL을 조작하기 위해 필요한 라이브러리는 Lambda layer로 생성하도록 하며, pymysql을 사용할 것을 권장합니다.
  • Lambda function name: store-manager
  • Lambda layer name: store-mysql

RDS 구성

  • MySQL과 호환 가능한 Aurora RDS cluster를 생성합니다.
  • DB의 storage는 암호화되어야 합니다.
  • 또한 Public 엑세스가 되지 않도록 구성합니다.
  • DB cluster identifier: store-rds

RDS 내에 table 생성 시 다음의 SQL문을 참고합니다.

CREATE TABLE `product` (
  product_id VARCHAR(255),
  name VARCHAR(255),
  PRIMARY KEY (product_id)
);

Lambda 구현

  • MySQL을 조작하기 위한 로직은 직접 개발해야 합니다.
  • 주어진 lambda_function.py의 내용을 참고할 수 있지만, 주어진 코드를 활용하지 않아도 무방합니다.
참고

배포된 lambda_function.py는 lambda_handler의 result = select_data(event)' 줄 끝에 불필요한 작은따옴표가 있어 그대로는 문법 오류가 납니다. 또한 insert_data/select_data는 TODO로 비어 있는 뼈대 코드입니다.

  • Lambda function을 invoke할 때 아래의 예제와 같은 payload를 입력할 수 있으며 예제와 동일한 구조를 가진 response를 반환해야 합니다.
Request payload Response
{"op": "POST", "product_id": "p-123", "name": "keyboard"} {"product_id": "p-123"}
{"op": "GET", "product_id": "p-123"} {"product_id": "p-123", "name": "keyboard"}
