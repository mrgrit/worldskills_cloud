Solution Architecture

회사의 서비스를 AWS 환경에 배포하기 위해 고가용성, 운영 효율성 등 클라우드 설계원칙을 고려하여 VPC, ECS(Service Connect), ECR, DynamoDB, CloudWatch 기반 시스템을 구축하는 과제입니다.

VPCECRECSELBCloudMapDynamoDBCloudWatch
📝 채점기준 보기

개요

클라우드 엔지니어로 회사의 서비스를 AWS 환경에 배포하기로 하였습니다. 주어진 요구사항과 고가용성, 운영 효율성 등 클라우드 설계원칙을 고려하여 시스템을 구축해야 합니다.

사용 기술

분류 항목
AWS VPC, ECR, ECS, ELB, CloudMap, DynamoDB, CloudWatch
Application Golang

선수 유의사항

주의

다음 유의사항을 고려하여 요구사항을 완성하시오.

  1. 문제에 제시된 괄호 <>는 변수를 뜻함으로 선수가 적절히 변경하여 사용해야 합니다.
  2. Security Group의 80/443 outbound는 anyopen하여 사용할 수 있도록 합니다.
  3. Bastion EÇ2는 채점을 위해 사용합니다. 서버들에 접속 문제가 생겨 채점에 불이익을 받지 않도록 합니다.
  4. 과제 종료 전 실행 중인 테스트 및 부하를 중지하여 서버에 문제가 없도록 해야 합니다.
  5. Tag 정보가 맞지 않거나 권한 문제가 생겨 채점이 불가하지 않도록 주의합니다.
  6. Region 설정이 필요한 리소스는 모두 서울 지역(ap-northeast-2)에 구성합니다.

3. 네트워크 구성

  • AWS VPC를 사용해 Public, Private 서브넷을 구성합니다.
  • 서브넷은 A존과 C존을 활용해 고가용성을 구성해야 하며 서브넷의 마스크는 자유롭게 구성합니다.
  • Public 서브넷은 인터넷에서 직접 접근 가능하며 Pirvate 서브넷은 인터넷으로 접근시 NAT G/W를 통하여 접근할 수 있도록 구성합니다.
  • Public 서브넷에 외부 사용자의 요청을 받을 수 있는 ALB 하나를 생성합니다.
항목 값
VPC name(tag) ws-vpc
VPC CIDR 10.101.0.0/16
Subnet(tag) ws-pub-a, ws-pub-c, ws-priv-a, ws-priv-c
Route table(tag) ws-pub-rt, ws-priv-rt-a, ws-priv-rt-c
ALB name(tag) gateway-alb-pub

4. Bastion

  • EC2를 활용해 Bastion 서버를 구성합니다.
  • 인터넷에서 접근 가능해야 하며 EIP를 활용하여 서버 재시작 후에도 IP가 변경되지 않도록 합니다.
  • Bastion은 채점용으로 사용됨으로 반드시 SSH를 통한 접속과 권한 문제가 없도록 합니다.
항목 값
EC2 type t3.micro
Image Amazon Linux2
Packages awscli, curl, docker, jq
Tag ws-bastion

5. Application

  • Gateway 서버는 Public 서브넷에 위치한 ALB와 연결되며, 외부로부터의 요청을 VPC 내부로 전달하는 엔드포인트를 제공하는 역할을 합니다.
  • NGINX 등과 같은 웹서버를 사용하거나 직접 개발하여 Gateway 서버를 구성합니다.
  • API 전달뿐 아니라 HTTP /health 요청 시 200 code를 반환할 수 있어야 합니다.
  • Product 애플리케이션은 REST API로 요청을 받아 DynamoDB에 데이터를 저장 및 읽기를 수행합니다.
  • 외부 사용자로부터의 요청은 Gateway 서버를 거쳐 전달됩니다.
항목 값
Binding port 8080

Product app API

API Parameters Response
POST /v1/item {"name": "jean", "owner": "kim"} {"result": "added", "uuid": "xxxx"}
GET /v1/item ?uuid=xxxx {"uuid": "xxxx", "name": "jean"}
GET /health - {"status": "OK", "app": "product"}

6. ECR

  • 애플리케이션이 포함된 컨테이너 이미지를 ECR로 올려서 관리하도록 합니다.
  • Private registry를 구성하고 보안 구성들을 진행합니다.
  • 업로드 시 스캐닝이 되어야 하며 이미지에 취약점이 존재하면 안 됩니다.
  • 또한 같은 이름의 이미지 태그가 있으면 업로드가 불가해야 하며 암호화되어 저장되도록 합니다.
  • 테스트를 위하여 ECR에 v1.0.0 태그를 갖는 이미지 하나를 업로드하도록 합니다.
항목 값
ECR name gateway, product
Installed packages curl

7. ECS

  • 아래 정보를 활용하여 ECS를 사용해 컨테이너를 프로비저닝 합니다.
  • 컨테이너는 EC2에서 운영되도록 합니다.
  • 컨테이너 내부로 SHELL 접근이 가능하도록 구성합니다.
  • 운영 환경임으로 latest 태그를 갖는 이미지를 활용해 task를 배포하지 않도록 유의하세요.
  • 또한 Gateway에서 Product 호출 시 ECS Service Connect를 사용하도록 구성합니다.
  • Service Connect를 위한 환경 변수는 각각 CONN_GATEWAY, CONN_PRODUCT를 사용합니다.
  • SHELL을 통해 Gateway 컨테이너 접근 후 curl을 통해 http://gateway에 호출하면 접근할 수 있어야 합니다.
항목 값
ECS cluster name ws-cluster
ECS Service name gateway-svc, product-svc
ECS TaskDefinition name gateway-td, product-td
EC2 type t3.small

8. DynamoDB

  • Product 애플리케이션은 DynamoDB를 사용하여 데이터를 처리합니다.
  • 테이블 구성 시 PAY_PER_REQUEST 모드를 사용하며 uuid, name, owner를 테이블의 키로 사용합니다.
  • 데이터 유실에 대비해 DynamoDB Encryption과 Arn을 활용한 백업과 PITR을 활성화하며 테이블의 삭제 방지를 구성합니다.
  • Encryption at rest을 위하여 CMK를 활용해 SSE 레벨의 테이블 암호화를 구성하도록 합니다.
항목 값
Table name product
Keys uuid, name, owner
Mode PAY_PER_REQUEST

9. Cloud Watch

  • ECS에서 사용하는 EC2의 CPU, Network In/Out bytes와 ALB의 4xx, 5xx 에러를 확인할 수 있는 그래프들을 가지는 "ProductService"라는 이름의 Dashboard를 구성합니다.
  • 만약 5분 안에 4xx 에러가 10개 이상 발생 시 알람이 울리도록 구성을 설정합니다.
  • 또한, ECS의 Container Insights를 활성화하여 클러스터에 존재하는 Task들의 CPU Utilization, Memory Utilization을 확인할 수 있도록 하고, CloudWatch Logs에서 task의 console output으로 전달되는 로그들을 모두 확인할 수 있도록 구성합니다.
항목 값
Dashboard name Product Service
Dashboard metrics EC2 CPU, EC2 Network, ALB 4xx error, ALB 5xx error
LogGroup name /ws/ecs/gateway, /ws/ecs/product
