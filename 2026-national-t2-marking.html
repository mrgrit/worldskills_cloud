1번 사전 준비

  1. 웹브라우저로 선수의 AWS 계정에 로그인 후 ap-southeast-1 Region으로 접속합니다.
  2. CloudShell에 접속해 아래 명령어를 입력하고 사용자의 AWS ID와 일치하는지 확인합니다.
    $ aws sts get-caller-identity --query Account --output text
  3. 아래 명령어를 실행해 채점환경을 준비합니다. (스크립트 사용 시 스킵)
    $ BUCKET_NAME="wsc2026-student-score-bucket-<선수 등번호>"
$ export STATE_MACHINE=$(aws stepfunctions list-state-machines --query stateMachines[].stateMachineArn --output text | grep wsc2026-student-score-workflow)

채점 전 S3 버킷과 DynamoDB의 데이터 클렌징이 완료된지 확인하며, 클렌징이 안되었다면 1-1과 1-5, 1-6은 틀린 것으로 간주합니다. 이후 S3 버킷에 input/test.csv 파일을 업로드 하며 60초 이후에 아래 명령어 들을 수행하여 워크플로가 정상 동작 하였는지 확인합니다.

참고

원문 불일치: 아래 check_data_cleansing은 input/, processed/, error/ 각 경로 목록이 1줄(폴더 객체만 존재)인지 확인하지만, 채점 스크립트(day2-1.sh)는 [ $(aws s3 ls s3://$BUCKET_NAME/ | wc -l) = 0 ]으로 버킷 최상위 목록이 비어 있는지(폴더 객체도 없음) 확인합니다. DynamoDB 항목 수 0 확인은 같습니다.

check_data_cleansing () {
  [ $(aws s3 ls s3://$BUCKET_NAME/input/ | wc -l) = 1 ] && [ $(aws s3 ls s3://$BUCKET_NAME/processed/ | wc -l) = 1 ] && \
  [ $(aws s3 ls s3://$BUCKET_NAME/error/ | wc -l) = 1 ] && [ $(aws dynamodb scan --table-name wsc2026-student-score --query Count --output text) = 0 ]
}

check_data_cleansing && echo "OK" && {
  wget -O test.csv https://notice-pg-qw7w2t3wk-asdf83xc4hc3-x28a3b8v1q91sr.s3.ap-northeast-2.amazonaws.com/2_s233asi43x/mod1/test.csv
  aws s3 cp test.csv s3://$BUCKET_NAME/input/
  aws stepfunctions start-execution --state-machine-arn $STATE_MACHINE --name $(date +%s)
  sleep 60
} || echo "Data not cleansed"

1-1. S3 Bucket + Folder Structure · 1점

채점 방법

  1. 아래 명령어를 실행합니다.
    aws s3api head-bucket --bucket $BUCKET_NAME 2>&1 > /dev/null && aws s3 ls s3://$BUCKET_NAME/
  2. 출력값이 아래와 일치하는지 확인합니다.
    PRE error/
PRE processed/
PRE input/
  • error와 processed만 있으면 정답. input 유무와 상관 없음.

3-6. Producer Running · 1점

채점 방법

  1. 아래 명령어를 입력합니다.
    aws dynamodb scan --table-name wsc2026-sensor-data --max-items 3 --query "Items[*].{sensorId:sensorId.S,timestamp:timestamp.S}" --output json
  2. 출력 결과가 JSON 형식으로 표시되고, sensorId와 timestamp 항목만 포함되어 있는지 확인합니다. timestamp 값은 ISO 8601 KST 형식 (YYYY-MM-DDTHH:mm:ss±HH:mm)으로 출력될 경우 정답으로 인정합니다.
    {
    "sensorId": "SENSOR-002",
    "timestamp": "2026-06-01T18:28:24+09:00"
}
  • Value 값은 다를 수 있으나 표기되는 Key는 모두 같아야 합니다. 단, timestamp의 경우 시간 자체는 다를 수 있으나, YYYY-MM-DDTHH:mm:ss±HH:mm 형식과 +09:00 형식으로 표기가 되어야 합니다.

5-2. Data Ingestion · 1점

채점 방법

  1. 아래 명령어를 입력합니다.
    CT=$(date +%H%M%S)
RES=$(curl -s -w '\n%{time_total}' -X POST -H 'Content-Type: application/json' \
      -d '{"device_id":"line-01-equip-'$CT'","metric":"temperature_c","value":82.4}' \
      http://$ALB/ingest)
BODY=$(echo "$RES" | head -1)
TIME=$(echo "$RES" | tail -1)
ID=$(echo "$BODY" | jq -r .id)

echo "POST ${TIME}s  $(awk -v t=$TIME 'BEGIN{print (t<=2)?"OK (2초 이내)":"FAIL (2초 초과)"}')"
echo "ID = $ID"

RES=$(curl -s -m 5 -w '\n%{http_code} %{time_total}' -X GET http://$ALB/v1/readings/$ID)
BODY=$(echo "$RES" | head -1)
CODE=$(echo "$RES" | tail -1 | cut -d' ' -f1)
TIME=$(echo "$RES" | tail -1 | cut -d' ' -f2)

if [ "$CODE" = "200" ]; then
    echo "GET ${TIME}s  OK (5초 이내)"
    echo "$BODY"
else
    echo "GET  FAIL (HTTP $CODE)"
fi
  2. 출력에 아래 POST와 GET이 모두 OK로 성공한 이력이 포함되어 있는지 확인합니다.
    POST 0.049125s  OK (2초 이내)
GET 1.007621s  OK (5초 이내)
  3. GET에서 반환된 데이터를 조합하여 유효성 검사를 합니다. 채점 스크립트(day2-5.sh)는 아래 명령으로 auth_token 값을 Base64 디코딩하여 출력합니다.
    curl --silent -X GET http://$ALB/v1/readings/$ID | head -n 1 | jq -r '.auth_token' | base64 -d
참고

원문에 유효성 검사의 판정 기준은 기재되어 있지 않습니다. 참고로 5-3의 응답 예시에서 auth_token(NmMwMjQ=)은 6c024로 디코딩되며, 이는 id의 마지막 5자리와 같습니다.

5-3. Success Rate · 1점

채점 방법

  1. 아래 명령어를 실행합니다.
    CT=$(date +%H%M%S)
BODY=$(curl -s -X POST -H 'Content-Type: application/json' \
       -d '{"device_id":"line-01-equip-'$CT'","metric":"temperature_c","value":82.4}' \
       http://$ALB/ingest)

    CT=$(date +%H%M%S)

5-5. Serverless Computing · 1.5점

주의

* 5-3이 성공한 경우만 득점이 인정됩니다.

채점 방법

  1. 아래 명령어를 입력하여 EC2와 ECS Fargate 개수를 확인합니다.
    EC2=$(aws ec2 describe-instances --region $REGION \
      --filters Name=instance-state-name,Values=running \
      --query 'length(Reservations[].Instances[])' --output text)

# shgold-cluster 의 Running 중인 Fargate 컨테이너 갯수
TASKS=$(aws ecs list-tasks --cluster shgold-cluster --desired-status RUNNING --region $REGION \
        --query 'taskArns[]' --output text)

if [ -z "$TASKS" ]; then
    FARGATE=0
else
    FARGATE=$(aws ecs describe-tasks --cluster shgold-cluster --tasks $TASKS --region $REGION | \
              jq '[.tasks[].containers[] | select(.lastStatus=="RUNNING")] | length')
fi

echo "Running EC2 인스턴스     : $EC2"
echo "Running Fargate 컨테이너 : $FARGATE"
  2. EC2 개수가 0이고, Running 상태인 Fargate 개수가 1개 이상이면 득점으로 인정합니다.
    Running EC2 인스턴스     : 0
Running Fargate 컨테이너 : 2
