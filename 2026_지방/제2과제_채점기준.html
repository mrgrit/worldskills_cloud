순번 

채점 항목 

0 

1) 웹브라우저로 선수의 AWS 계정에 로그인 후 각 문제에서 지시하는 AWS region으로 이동합니다. 

2) CloudShell을 실행합니다. 

3) 제공된 채점 스크립트 파일을 업로드 하여 사용할 수 있습니다. 다음과 같이 실행합니다. 

$ bash mark.sh 

1-1 

1) ap-northeast-1 리전으로 이동합니다. 

2) 새로운 cloud shell을 실행합니다. 

3) 아래 명령어를 실행합니다. 

$ aws ec2 describe-vpcs --filter Name=tag:Name,Values=sharing-vpc --query Vpcs[].VpcId --output text 

3) vpc id가 출력되는지 확인합니다. 

1-2 

1) 아래 명령어를 실행합니다. 

$ aws ec2 describe-subnets --filter Name=tag:Name,Values=sharing-subnet-a --query "Subnets[0].CidrBlock" --output text 

$ aws ec2 describe-subnets --filter Name=tag:Name,Values=sharing-subnet-b --query "Subnets[0].CidrBlock" --output text 

2) 출력되는 결과가 "10.100.0.0/24", "10.100.1.0/24"인지 확인합니다. 

1-3 

1) 아래 명령어를 실행합니다. 

$ aws autoscaling describe-auto-scaling-groups --query AutoScalingGroups[].AutoScalingGroupName --output text 

2) 출력되는 결과가 "sharing-asg"인지 확인합니다. 

1-4 

1) 아래 명령어를 실행합니다. 

$ aws efs describe-file-systems --query FileSystems[].Name --output text 

2) 출력되는 결과가 "sharing-efs"인지 확인합니다. 

1-5 

1) 아래 명령어를 실행합니다. 

$ aws efs describe-file-systems --query "FileSystems[?Name=='sharing-efs'].Encrypted" --output text 

2) 출력되는 결과가 "True"인지 확인합니다. 

1-6 

1) 아래 명령어를 실행합니다. 

$ fs_id=$(aws efs describe-file-systems --query "FileSystems[?Name=='sharing-efs'].FileSystemId" --output text) 

$ aws efs describe-lifecycle-configuration --file-system-id $fs_id --query LifecyclePolicies[].TransitionToIA --output text 

2) 출력되는 결과가 "AFTER_30_DAYS"인지 확인합니다. 

1-7 

1) 아래 명령어를 실행합니다. 

$ aws efs describe-mount-targets --query MountTargets[].AvailabilityZoneName --file-system-id $fs_id --output text 

2) 출력되는 결과가 "ap-northeast-1a", "ap-northeast-1b"인지 확인합니다. 

1-8 

1) EC2 콘솔로 이동합니다. 

2) 생성되어 있는 모든 EC2 인스턴스를 삭제(terminate)합니다. 

3) 인스턴스가 새로 실행되면 SSM으로 연결합니다. 

4) 아래 명령어를 실행합니다. 

$ sudo su - 

$ df | grep /mnt/efs 

5) 출력되는 결과가 "10.100.x.x"와 "/mnt/efs"를 포함하는지 확인합니다. 

1-9 

1) SSM에 연결된 상태에서 아래 명령어를 실행합니다. 

$ echo "marking9999" > /mnt/efs/mark9999.txt 

$ ls /mnt/efs 

2) 출력되는 결과가 "mark9999.txt"를 포함하는지 확인합니다. 

1-10 

1) 1-8에서 사용하지 않은 다른 인스턴스에 SSM으로 연결합니다. 

2) 아래 명령어를 실행합니다. 

$ ls /mnt/efs 

2) 출력되는 결과가 "mark9999.txt"를 포함하는지 확인합니다. 

2-1 

1) ap-northeast-2 리전으로 이동합니다. 

2) 새로운 cloud shell을 실행합니다. 

3) 아래 명령어를 실행합니다. 

$ aws s3 ls | grep "korea-skills-research-data" 

3) 출력되는 결과가 "korea-skills-research-data"를 포함하는지 확인합니다. 

2-2 

1) 아래 명령어를 실행합니다. 

$ aws s3 ls | grep "korea-skills-research-result" 

2) 출력되는 결과가 "korea-skills-research-result"를 포함하는지 확인합니다. 

2-3 

1) 아래 명령어를 실행합니다. 

$ aws athena get-work-group --work-group research --query WorkGroup.Configuration.BytesScannedCutoffPerQuery --output text 

2) 출력되는 결과가 "1073741824"(1GB)인지 확인합니다. 

2-4 

1) 아래 명령어를 실행합니다. 

$ aws athena get-work-group --work-group research --query "WorkGroup.Configuration.ResultConfiguration.OutputLocation" --output text 

2) 출력되는 결과가 "s3://korea-skills-research-result"를 포함하는지  확인합니다. 

2-5 

1) 아래 명령어를 실행합니다. 

$ aws glue get-table --database-name research --name employee --query Table.Name --output text 

2) 출력되는 결과가 "employee"인지 확인합니다. 

2-6 

1) 아래 명령어를 실행합니다. 

$ aws glue get-table --database-name research --name survey --query Table.Name --output text 

2) 출력되는 결과가 "survey"인지 확인합니다. 

2-7 

1) 아래 명령어를 실행합니다. 

$ query_id=$(aws athena start-query-execution --work-group research --query-string "select * from research.employee where name = 'name'" --query "QueryExecutionId" --output text) 

$ aws athena get-query-results --query-execution-id $query_id --query ResultSet.Rows[].Data --output text | wc -l 

2) 출력되는 결과가 "3"인지 확인합니다. 

2-8 

1) 아래 명령어를 실행합니다. 

$ named_queries=$(aws athena list-named-queries --work-group research --query NamedQueryIds --output text) 

$ aws athena batch-get-named-query --named-query-ids $named_queries --query NamedQueries[].Name --output text 

2) 출력되는 결과가 "research-query1", "research-query2"인지 확인합니다. 

2-9 

1) 아래 명령어를 실행합니다. 

$ query_string=$(aws athena batch-get-named-query --named-query-ids $named_queries --query "NamedQueries[?Name=='research-query1'].QueryString" --output text) 

$ query_id=$(aws athena start-query-execution --work-group research --query-string "$query_string" --query "QueryExecutionId" --output text) 

$ aws athena get-query-results --query-execution-id $query_id --query ResultSet.Rows[].Data --output text 

2) 출력되는 결과가 "result", "3.8"인지 확인합니다. 

2-10 

1) 아래 명령어를 실행합니다. 

$ query_string=$(aws athena batch-get-named-query --named-query-ids $named_queries --query "NamedQueries[?Name=='research-query2'].QueryString" --output text) 

$ query_id=$(aws athena start-query-execution --work-group research --query-string "$query_string" --query "QueryExecutionId" --output text) 

$ aws athena get-query-results --query-execution-id $query_id --query ResultSet.Rows[].Data --output text 

2) 출력되는 결과가 "result", "4.5"인지 확인합니다.

$ aws dynamodb describe-table --table-name catalog --query Table.DeletionProtectionEnabled —output text 

$ aws dynamodb describe-table --table-name secret --query Table.DeletionProtectionEnabled --output text 

2) 출력되는 결과가 "True", "True"인지 확인합니다. 

3-3 

1) 아래 명령어를 실행합니다. 

$ aws dynamodb describe-table --table-name catalog --query Table.SSEDescription.Status —output text 

$ aws dynamodb describe-table --table-name secret --query Table.SSEDescription.Status --output text 

2) 출력되는 결과가 "ENABLED", "ENABLED"인지 확인합니다.

3-5 

1) 아래 명령어를 실행합니다. 

$ aws iam get-policy --policy-arn arn:aws:iam::$ACCOUNT_ID:policy/employee-policy --query Policy.PolicyName --output text 

2) 출력되는 결과가 "employee-policy"인지 확인합니다. 

3-6 

1) 아래 명령어를 실행합니다. 

$ aws iam list-attached-role-policies --role-name employee-role --query AttachedPolicies[].PolicyName --output text 

2) 출력되는 결과가 "employee-policy"인지 확인합니다. 다른 출력이 존재해서는 안됩니다. 

3-7 

1) 아래 명령어를 실행합니다. 

$ credentials=$(aws sts assume-role --role-arn arn:aws:iam::$ACCOUNT_ID:role/employee-role --role-session-name marking --query Credentials.[AccessKeyId,SecretAccessKey,SessionToken] --output text) 

$ export AWS_ACCESS_KEY_ID=$(echo $credentials | awk '{print $1}') 

$ export AWS_SECRET_ACCESS_KEY=$(echo $credentials | awk '{print $2}') 

$ export AWS_SESSION_TOKEN=$(echo $credentials | awk '{print $3}') 

$ aws dynamodb put-item --table-name catalog --item '{"name": {"S": "apple"}, "type": {"S": "fruit"}}' 

$ aws dynamodb get-item --table-name catalog --key '{"name": {"S": "apple"}}' --query Item.type.S --output text 

2) 출력되는 결과가 "fruit"인지 확인합니다.
