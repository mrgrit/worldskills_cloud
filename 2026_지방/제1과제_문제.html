1. 요구사항 

당신은 WorldPay의 유저 관리 시스템을 구축하는 업무를 수행해야 합니다. WorldPay는 전 세계 사람들의 결제를 쉽게 도와주는 서비스로, 중요한 정보의 유출을 막고 고가용성을 확보하도록 설계되었습니다. 주어진 요구사항에 따라 고가용성, 보안, 확장성 등을 고려한 인프라를 구축해야 합니다.

2. 선수 유의사항 

  ※ 다음 유의사항을 고려하여 요구사항을 완성하시오. 

  1) 기계 및 공구 등의 사용 시 안전에 유의하시고, 필요하면 안전장비 및 복장 등을 착용하여 사고를 예방하여 주시기 바랍니다. 

  2) 작업 중 화상, 감전, 찰과상 등 안전사고 예방에 유의하시고, 공구나 작업도구 사용 시 안전보호구 착용 등 안전수칙을 준수하시기 바랍니다. 

  3) 작업 중 공구의 사용에 주의하고, 안전수칙을 준수하여 사고를 예방하여 주시기 바랍니다. 

  4) 경기 시작 전 가벼운 스트레칭 등으로 긴장을 풀어주시고, 작업도구의 사용 시 안전에 주의하십시오. 

  5) Bastion EC2는 채점 시 사용하기 때문에 연결 및 권한 문제가 발생하지 않도록 주의합니다. Bastion EC2에 접근 불가한 경우 채점에 불이익이 있을 수 있습니다. 

  6) 문제에 변수로 지정되는 부분은 적절히 변경하여 사용 하도록 합니다. 

  7) 문제의 효율을 위해 Security Group의 80/443 outbound는 anyopen 하여 사용 할 수 있도록 합니다. 

  8) 과제에 지급된 바이너리를 변경해서는 안됩니다. 바이너리를 변경하거나 다른 바이너리를 사용할 경우 0점 처리 될 수 있습니다. 

  9) EC2의 OS image는 Amazon Linux 2023를 사용합니다. 

  10) 문제에서 제시한 Name tag에 유의하여 리소스를 생성해야 합니다. Name tag가 일치하지 않는 리소스를 생성한 경우 채점에 불이익이 있을 수 있습니다. 

  11) 문제에서 명시되지 않은 경우 ap-northeast-2(서울) 리전에 리소스를 생성합니다. 

 

3. VPC 

WorldPay는 유저의 정보를 DB에 안전하게 저장하기 위해 네트워크 수준의 접근 제어를 구현해야 합니다. 이를 위해 2개의 VPC를 생성하고, VPC Peering을 구성하여 서로 통신할 수 있게 구성합니다. Peering 된 VPC 간에는 DNS name resolution이 가능해야 합니다. 

Public subnet은 인터넷과 직접적인 통신이 가능하며, app subnet은 NAT gateway를 통해 인터넷에 접근할 수 있도록 합니다. DB subnet은 인터넷과 통신이 불가능하고, 오직 app subnet과의 통신만 허용하도록 합니다. DB subnet의 통신을 제어하기 위해 NACL을 생성하여 사용하고, 인터넷(0.0.0.0/0)과의 통신을 허용하지 않도록 설정합니다. VPC 내에서 SecretsManager 서비스에 접근하고자 하면 PrivateLink(VPC endpoint)를 통해 인터넷 외부를 거치지 않도록 합니다. 

 

- VPC Name tag: worldpay-app-vpc, world-db-vpc 

- VPC CIDR: 10.0.0.0/16, 10.100.0.0/16 

- Availability Zone: ap-northeast-2a, ap-northeast-2c 

- VPC Peering Name tag: worldpay-vpc-peering 

- DB subnet NACL Name tag: worldpay-db-nacl 

- 두 VPC 모두 Flow log 활성화 

- Subnet 정보

4. Bastion 

Bastion 용도로 사용할 EC2 instance를 생성합니다. 채점 시 사용하므로 Administrator에 준하는 IAM 권한을 부여하여 권한 문제가 발생하지 않도록 하고, SSH나 Session Manager를 통한 접근에 문제가 생기지 않도록 합니다. 

 

- Instance type: t3.micro 

- Instance name tag: worldpay-bastion 

- Image: Amazon Linux 2023 

- Subnet: worldpay-pub-subnet-a 

5. Application 

WorldPay의 애플리케이션은 HTTP 요청을 처리할 수 있는 웹 애플리케이션입니다. Python/FastAPI로 개발되었으며, Amazon Linux 2023/x86 환경에서 빌드되고 테스트 되었습니다. 

애플리케이션이 API 요청을 처리하기 위해 MySQL과 통신을 할 수 있어야 합니다. 애플리케이션 구동 시 Secrets Manager에 저장된 'worldpay-secret' 을 참조하여 MySQL 서버와의 통신을 시도하게 됩니다. 만약 secret이 제대로 생성되지 않거나 MySQL과의 통신할 수 없는 경우 애플리케이션이 구동되지 않습니다.

6. ALB 

WorldPay의 애플리케이션의 부하분산을 위해 ALB를 구성합니다. ALB는 public subnet에 구성합니다. 만약 애플리케이션에 구현되지 않은 API 요청을 받으면 애플리케이션으로 요청이 전달되어서는 안 되며, Fixed response 기능을 활용해 HTTP status code 403을 반환하도록 합니다.  

 

- ALB Name tag: worldpay-alb 

- Subnet: worldpay-pub-subnet-a, worldpay-pub-subnet-c 

- 비정상 요청 시 403 response 반환 

- 외부에서 HTTP 프로토콜, 80 port를 통해 접근 

 

 

7. ASG 

애플리케이션은 EC2 환경에 배포하도록 합니다. 고가용성과 확장성을 위해 Auto scaling group을 생성해야 하며, 최소 2대 이상의 instance가 배포되어 있어야 합니다. 확장성을 위해 CPU 사용량이 70%를 넘으면 새 인스턴스를 생성하도록 정책이 설정되어야 합니다. 

 

- Auto scaling group name: worldpay-asg 

- Instance Name tag: worldpay-app 

- Instance type: t3.micro 

- Min size: 2 

8. RDS 

WorldPay의 유저 정보를 저장하기 위해 RDS를 생성합니다. 데이터베이스의 데이터를 안전하게 보관하기 위해 KMS로 암호화해야 합니다. 또한 Well-known port인 3306 대신 다른 번호를 사용하여 무차별 스캔 공격으로부터 보호하고자 합니다. 

 

- RDS cluster identifier: worldpay-rds 

- Engine: aurora-mysql8.0 

- Instance class: db.t3.medium 

- Port: 3307 

- Public access 비활성화 

- Subnet: worldpay-db-subnet-a, worldpay-db-subnet-c 

- KMS encryption 활성화 

 

애플리케이션이 정상적으로 동작하기 위해서는 RDS에 적절하게 database와 table이 생성되어 있어야 합니다. 아래의 SQL 구문을 참고하여 table을 생성하도록 합니다. 

CREATE TABLE `worldpay`.`users` ( 

  uid INT AUTO_INCREMENT, 

  name VARCHAR(255), 

  age INT, 

  PRIMARY KEY (uid) 

); 

 

 

 

9. Secrets Manager 

애플리케이션이 데이터베이스에 접근하기 위해서는 username, password, host 등의 정보가 필요합니다. 이러한 정보들을 secret으로 생성하여 관리하고자 하며, 아무나 secret에 접근하는 것을 막기 위해 KMS CMK(Customer Managed Key)를 사용하여 암호화해야 합니다. 애플리케이션이 과도한 권한을 갖지 않도록 admin이 아닌 user를 사용하도록 합니다. (username이 “admin”이 되면 안 됨) 

 

- Secret name: worldpay-secret 

- Encryption key: CMK 

- Secret 예제(실제 secret 내용과 다를 수 있음): 

{"username": "app", "password": "1q2w3e4r", "host": "worldpay-rds.rds.amazonaws.com"} 

10. CloudWatch Logs 

애플리케이션에서 발생하는 로그를 수집해야 합니다. 로그가 발생하면 최대 5분 내로 지정된 Log group으로 전송되어 애플리케이션의 로그를 확인할 수 있어야 합니다. 또한 비용을 절감하기 위해 최대 30일 동안만 로그를 보관하도록 설정합니다. 

 

- Log group name: worldpay-log-group 

 

 

11. CloudWatch  

서비스 중에 발생하는 이상 징후를 탐지하기 위해 대시보드를 생성해야 합니다. ALB에서 발생하는 Fixed response의 값의 개수(HTTP_Fixed_Response_Count)와 ASG의 인스턴스들의 CPU 사용량의 평균을 보여주는 대시보드를 생성합니다. 

 

- Dashboard name: worldpay-dashboard
