Small ChallengeSecure networking

NAT G/W와 Internet G/W 없이 프라이빗 서브넷의 EC2가 S3 원본·백업 버킷과 SQS에 접근하고, 2024 폴더 업로드만 백업 버킷으로 복제·SQS 이벤트가 발생하도록 하며, EC2 접근은 Instance Connect로만 허용하도록 구성하는 과제입니다.

VPCEC2S3SQSIAM
📝 채점기준 보기

개요

J회사가 현재 비용 이슈로 인해 Nat G/W와 internet G/W를 이용하지 않고, J회사의 EC2인스턴스가 S3의 원본 버킷과 백업 버킷 접근을 해야 하며, 백업 버킷은 / 경로에만 접근을 해야 합니다. SQS 서비스에도 접근을 해야 합니다. S3는 원본 버킷과 백업 버킷으로 이루어져 있으며, 원본 버킷에 / 경로에 파일 업로드 할 시, 백업 버킷에 / 경로에 파일 업로드가 되지 말아야하며, 원본 버킷의 2024폴더에 파일업로드 시, 백업 버킷의 2024폴더에도 파일업로드가 되어야하며, 백업 버킷에 2024폴더에 파일이 올라오면 SQS에 이벤트가 발생해야합니다. 백업 버킷의 / 경로에 파일 업로드 되었을 경우에 SQS 이벤트가 발생하면 안됩니다. J회사의 EC2인스턴스에 접근할 때 Keypair, Session Manager, 직렬 콘솔을 이용하지 않고, Instance Connect 로만 J회사의 EC2인스턴스에 접근을 할 수 있어야 합니다. EC2 Instance Connect Endpoint는 J-company-priv-sub-a가 아닌 J-company-priv-sub-b에 두어, J-company-priv-sub-b를 통해서 EC2인스턴스에 접근을 해야 합니다. 아래의 내용을 보고 알맞게 구성을 해야 합니다. 백업 버킷으로 파일이 복사될 때 4분 이내로 완료 되어야 합니다.

사용 기술

분류 항목
AWS VPC, EC2, S3, SQS, IAM

선수 유의사항

  1. 선수의 계정에는 비용 제한이 존재하며, 이보다 더 높게 과금될 시 계정사용이 불가능할 수 있습니다.
  2. 문제에 제시된 괄호 박스 <> 는 변수를 뜻함으로 선수가 적절히 변경하여 사용해야 합니다.
  3. 과제 종료 시 진행 중인 테스트를 모두 종료하여 서버에 부하가 발생하지 않도록 합니다.
  4. 모든 리소스는 eu-west-1 리전에 구성합니다.
  5. 이름이 명시되어있지 않는 것들은 선수가 적절히 이름을 명시해야 합니다.
  6. Bastion EC2는 채점 시 사용되기 때문에 종료되거나 연결 문제, 권한 문제 등으로 발생할 수 있는 불이익을 받지 않도록 주의하시기를 바랍니다.
  7. 제공자료는 수정 없이 사용합니다. 제공자료를 수정해서 사용하면 불이익을 받을 수 있습니다.
